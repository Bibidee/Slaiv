# Security boundary

SLAIV separates **who may trigger work** from **who determines truth or settlement**.

- Policy creation and claim filing are identity-bound: the policy `holder` and claim `claimant` must equal the transaction sender. Another wallet cannot create or file as someone else.
- `CLAIMANT_ASSERTION` evidence remains claimant-only because it represents the claimant's own assertion, and is stored as bounded real text (not merely a hash) so GenLayer judgment can inspect what the claimant actually said. `PUBLIC_SOURCE` evidence may be appended by any wallet while evidence is open, must be an `https://` reference, and is independently retrieved by the leader and every validator via `gl.nondet.web` at judgment time (bounded source count and response size) rather than trusted as a label; a fetch failure is recorded as unavailable rather than silently treated as content.
- Evidence quotas are kind- and phase-scoped, not a single shared cap: pre-review `CLAIMANT_ASSERTION` and `PUBLIC_SOURCE` evidence each have their own bounded pool (plus a per-wallet cap on public evidence), the verified `PROTOCOL_FACT` slot is reserved independently of either pool, and appeal evidence draws from its own separate reserved pool that pre-review spam can never exhaust. No combination of outsider `PUBLIC_SOURCE` submissions can block protocol-fact recording or a claimant's later appeal evidence.
- Duplicate public evidence is detected by canonical fields (`kind`, `reference`, `source`, `content_hash`), not by the caller-chosen `evidence_id` alone, so an attacker cannot bypass the cap by resubmitting the same source under a fresh id.
- There is no protocol-authority key in the permissionless design. Any wallet may call `verify_protocol_finality`, but the caller supplies only a candidate 32-byte GenLayer transaction hash -- not a source URL. The contract resolves the official RPC endpoint for the policy's network internally (`RPC_ENDPOINTS`), so the caller cannot influence which source is queried at all.
- The caller cannot pass `FINAL`, validator identity, network, incident class, or event timestamp as authoritative inputs. The Intelligent Contract queries the official RPC (`eth_getTransactionByHash`) inside a GenLayer non-deterministic block; leader and validators independently re-query it and deterministically derive the settlement-critical protocol fields from its structured JSON, and must agree exactly. Incident classification is deterministic code, not an LLM judgment call: `MISSED_EXECUTION_WINDOW` only when the policy's validator appears in the RPC response's `leader_timeout_validators`, an explicit, validator-scoped list. `rotation_count > 0` and `appeal_failed > 0` are each insufficient alone and never establish an incident. `MISSED_APPEAL_WINDOW` is not supported: the official RPC exposes `appeal_leader_timeout`/`appeal_validators_timeout` only as transaction-wide booleans with no field binding either one to a specific validator address, so a genuine appeal timeout on an unrelated validator could not be distinguished from one on the insured validator. This event class was removed after a live audit found exactly that gap (see `docs/DEPLOYMENT.md`, superseded-deployment entry) rather than ship an unverifiable validator binding.
- Protocol verification fails closed when the RPC is unavailable, returns a JSON-RPC error or a null/missing transaction, the network has no verified RPC mapping (currently only `studionet`; `testnetAsimov`/`testnetBradbury` are unverified), the returned transaction hash doesn't match the candidate, or the incident/validator/timestamp fields don't unambiguously match the policy. Because `SUBJECT_NETWORKS` is derived directly from `RPC_ENDPOINTS`, `testnetAsimov`/`testnetBradbury` are rejected even earlier, at `create_policy` -- a policy can never be created promising coverage SLAIV cannot currently verify.
- A verified protocol event is single-use **per policy** (`policy_id + network + validator + event_id`), not globally: two independently insured policies covering the same validator may both legitimately settle against one genuine event, but a single policy cannot reuse the same event across two of its own claims.
- `review_slashing_claim` and `review_appeal` are permissionless triggers. The caller cannot pass a verdict. GenLayer consensus derives the verdict from immutable policy terms, claim state, and stored (and, for `PUBLIC_SOURCE` items, freshly retrieved) evidence; deterministic code revalidates settlement-critical fields before state changes. Validators independently derive `eligibility`, `incident_class`, `covered_event`, `exclusion_triggered`, and a `loss_fraction_bps` drawn from a small fixed band (`0/2500/5000/7500/10000`) -- never a free-form loss amount -- and the contract computes `eligible_loss = documented_loss * loss_fraction_bps // 10000` deterministically in code, never trusting an LLM-computed amount. Consensus agreement is scoped to these settlement-critical fields (plus a canonicalized, order-independent set of supported evidence ids); differences in `reasoning_summary` wording or `confidence` never block consensus or cause a legitimate verdict to be rejected.
- An `UNRESOLVED` appeal disposition does not strand the claim. The claim remains `APPEALED` with `appeal_resolved=false`, and `review_appeal` may be triggered again by any wallet until it actually resolves (`UPHOLD`/`MODIFY`/`OVERTURN`); a third party cannot destroy the claimant's live appeal right, and the claimant cannot be permanently blocked from a resolvable outcome.
- Appeal initiation remains claimant-only because appealing is the claimant's procedural choice. A one-hour appeal window protects denied and partially approved claims from third-party finalization. The claimant may finalize their own terminal result earlier, which acts as a voluntary waiver of that appeal window.
- Finalization is otherwise permissionless when no live appeal right is being destroyed: approved claims, claims after resolved appeal, and denied/partially-approved claims after appeal-window expiry may be finalized by any wallet.
- The finalizer cannot choose payout. Payout consumes the stored effective verdict, uses integer arithmetic, applies the policy deductible and then the coverage cap, and rejects double finalization.
- Fetched pages, public evidence, and claimant text are untrusted data, never instructions. Consensus prompts explicitly treat source content as evidence rather than instructions.
- Underlying protocol finality and GenLayer transaction finality are separate. Pending underlying finality blocks semantic judgment and payout.
- Policies are immutable after activation. Network, validator, coverage window, event membership, exclusions, deductible, and coverage limit are deterministic boundaries. `create_policy` and `submit_claim` both reconstruct stored state from an explicit field allowlist -- unknown or injected keys in caller-supplied JSON (e.g. a prompt-injection payload disguised as an extra field) are discarded before storage and can never reach an LLM prompt. Every variable-size field (exclusions, evidence source/content/URL length, supported-evidence-id count, reasoning length, claim explanation) is contract-side bounded.
- SLAIV does not fabricate unsupported protocol events. If an official source cannot prove a candidate event, the correct state is `AWAITING_FINALITY`.
- Settlement-critical timestamps (`appeal_deadline_ts`, `decision_at_ts`, etc.) come from GenVM's deterministic intercepted `datetime.now()` for the current consensus round, not validator-local wall-clock time -- every validator computes the identical value for a given write, which is why these timestamps never cause consensus disagreement (see `tests/direct/test_security_matrix.py::test_time_handling_is_deterministic_across_validators`).
